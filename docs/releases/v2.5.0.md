# RAGOps v2.5.0

## New

- **`ragops init --candidate LOGS`**: give the logs of a later run next to the baseline logs; answers are matched by id or question text and a `candidate.json` plus `compare-report.md` are written, so the first regression check needs no hand-written files.
- **`ragops policy-suggest`**: generates a slice-aware release policy v2 from an accepted baseline (one slice per language, category and severity with enough cases; minimums set from the lowest baseline value minus a margin). Review it before use, then apply it with `ragops gate-v2`.
- **Plain-language gate reasons**: `ragops explain` and the pull-request comment now say in one sentence why each gate failed (new `summary` field in the explanation JSON).
- **`ragops calibrate` suggests a threshold**: `suggested_threshold` is the cutoff that best fits your human labels within your false-pass limit.
- **Weekly workflow** (`weekly.yml`) runs the tests and grounding benchmark against the newest dependencies.
- **Mutation testing** with `mutmut` (`pip install -e '.[mutation]'`); new tests raised the kill rate on four modules from 65% to 91%.

## Research

- Selecting evidence with BM25 before NLI did not help (AUROC 0.68; sentence-mean 0.63 versus lexical 0.76). Explorer highlights land on annotated RAGTruth hallucination spans about twice as often as chance (precision 5.5 to 11.5%, recall 31 to 41%) but also mark about 16% of clean text: a reading aid, not a detector. See [RAGTruth](../case-study-ragtruth.md) and [semantic evaluator](../semantic-evaluator.md).

## Compatibility

No breaking changes. The calibration report schema gains an optional `suggested_threshold` field; the explanation JSON gains `summary`. Existing 2.4.x baselines remain valid. Adapters for Langfuse/OpenAI/Anthropic still follow documented export shapes and have not been run against a live account export.
